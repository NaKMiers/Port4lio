### Factual corrections (no behavior change, no question needed)

- **C1 (Open Question 1 settled by evidence).** No handler cache and no `withMcpAuth`. The route verifies the token, then calls `createMcpHandler(server => registerTools(server, token))`. The initializer closes over `{ tokenId, name, scopes }`, so it registers only the permitted tools, and every tool reads the token from the closure. This is exactly what happens per request today, with a closure added. The design's "`handlerFor(scopes)` / `Map<scopeKey, handler>`" is replaced by this.
- **C2 (R2-12).** `update_profile` is `publish` in both tables. Superseded by R8 (D24): scene 3 needs only `read`, because the resume is never written by an agent.
- **C3 (R2-14).** Profile section keys map to `Profile` fields: `identity` (fullName, username, jobTitle, description, avatar, backgroundImage, publicLocation, socials), `about` (profileHeading, profileSubHeading, stats, aboutMe), `career` (skills, experience, education, certificates), `offering` (serviceHeading, serviceSubHeading, briefServices, services), `work` (workHeading, workSubHeading, projects), `cvFile` (the public `cv` string field), `resume` (the private `resume` block, the CV with contact details).
- **C4 (R2-15).** `get_me` moves to phase 2, where `post-service` exists. Phase 1 ships `get_profile` and the whiteboard reads.
- **C5 (R2-17).** The alias's three tool definitions accept the scope set {`read`, `whiteboard:legacy`}. `runTool` step 1 checks "the token holds any scope in `def.scopes`". This is required for approved premise 7.
- **C6 (R2-19).** Prompts are registered per request like tools, so their text is rendered for the token. They say "if `publish_post` is in your tool list", never "if the token allows".
- **C7 (R2-21).** `loadPublicResume` in `src/lib/profile-data.ts` documents that the contact details "are never served as machine-readable JSON". `get_me`/`get_profile` become the one token-gated exception, and that comment is updated in the same change. This is required by the house rule on stale comments.
- **C8 (R2-8, R2-16).** Revalidation lives inside services (approved in the design, "Where revalidation lives"). This covers `illustratePost` on a live post, even with `publish: false`, and `taxonomy-service`, which keeps today's `revalidatePath('/blog')` from the kind PATCH. The e2e check adds `illustrate_post` on a live post and `save_taxonomy` refreshing `/blog`.
- **C9 (R2-10, R2-11).** `create_draft` validates every field and renders the markdown **before a single insert**, so a failure leaves no post behind. The slug derivation reuses `slugify` + `SLUG_PATTERN` + `isReservedSlug` exactly as `validateManualSpec` does (`generate.ts:768-824`). An empty or reserved result is an `isError`. Both are required so the approved `create_draft` contract never leaves a bare draft holding a slug.

- **C10 (R2-3, reconciling two approved statements).** No tool relies on clipping:
  - List tools page by cursor: `list_posts`, `whiteboard_search` (keeps its `limit` of at most 25), `list_taxonomy`.
  - `get_post` pages the body.
  - Single-object tools are capped by construction: `get_me` returns titles only for goals and posts, and at most 5 posts; `get_briefing` returns at most the top 10 posts; profile sections are returned whole.
  - `runTool`'s clip stays as a last-resort safety net. It appends an explicit `[truncated: N chars dropped]` marker and logs a warning, and a test asserts no tool reaches it with seeded maximum-size data.

## Section 1: Architecture review

### Request flow (amended by C1)

```
  POST /api/mcp
    │
    ├─ guardAgent(request, { accept: ['p4_'] })        rate limit by IP ─▶ bearer ─▶ AgentToken   (fail closed)
    │     └─▶ token = { tokenId, name, scopes }
    │
    ├─ createMcpHandler(server => {                     mcp-handler builds a fresh McpServer per request
    │      for (def of REGISTRY) if (allowed(def, token.scopes)) server.registerTool(def.name, ..., args => runTool(def, args, token))
    │      for (p of PROMPTS)    if (allowed(p, token.scopes))  server.registerPrompt(p.name, ..., () => p.render(token.scopes))
    │   })(withAcceptBoth(request))
    │
    └─ sseToJson(response) ─▶ noStore ─▶ 200 JSON
```
